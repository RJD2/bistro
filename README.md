# Бот Быстротест

Вопрос состоит из слова `word`, результатов `options` и ассоциаций `associo`. Игрок выбирает ассоциацию, а бот сообщает соответствующий результат из `options`. Порядок элементов совпадает:

```json
{"word": "цезарь", "options": "повар,император", "associo": "салат,Рим"}
```

На вопрос «Цезарь» бот показывает кнопки «Салат» и «Рим». Выбор «Салат» дает результат «повар», выбор «Рим» — «император». В ответах и статистике сохраняются результаты из `options`.

## Структура проекта

Код приложения собран в пакет `bistro`, а модули сгруппированы по назначению:

```text
.
├── bistro/
│   ├── __main__.py       # Запуск через python -m bistro
│   ├── bot.py            # Сборка бота и регистрация обработчиков
│   ├── config.py         # Настройки из переменных окружения и .env
│   ├── database/         # Подключение к базе и модели SQLAlchemy
│   ├── handlers/         # Команды, callback-обработчики и состояния FSM
│   ├── services/         # Автотест и выбор доступных вопросов
│   ├── charts/           # Построение, хранение ссылок и обновление диаграмм
│   └── ui/               # Клавиатуры, меню, тексты и методы сообщений Telegram
├── migrations/           # Инициализация базы и добавление исходных вопросов
├── tests/                # Автоматические тесты
├── bot.py                # Короткая точка входа для прежней команды запуска
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
└── entrypoint.sh
```

Импорты внутри приложения используют полные пути от `bistro`, например `from bistro.database.models import Question`. Команды запуска и миграций выполняются из корня проекта.

## Настройка

Скопируйте `.env.example` в `.env` и заполните:

- `TOKEN` — токен Telegram-бота.
- `ADMIN_ID` — числовой Telegram ID владельца. При `0` или отсутствии значения добавление вопросов отключено.
- `DB` — адрес PostgreSQL для локального запуска. В Docker Compose адрес задается автоматически.

## Клавиатура бота

Отправьте `/stop`, чтобы убрать нижнюю клавиатуру бота и вернуть обычную клавиатуру Telegram. В группе можно использовать `/stop@имя_бота`; клавиатура убирается для участников группы. Вернуть меню можно командой `/start`.

Команда скрывает только меню: прогресс, текущий вопрос и черновики сохраняются, Автотест продолжает работать по своему расписанию. Для отключения ежедневных вопросов используйте `/autotest`.

## Статистика

Нажмите «📊 Статистика» в меню после `/start` или отправьте `/statistics`. Бот покажет все слова, на которые вы уже ответили в обычном Быстротесте или Автотесте, по 10 слов на странице. Кнопки «Далее» и «Назад» позволяют просмотреть весь список. Нажмите на слово, чтобы открыть график распределения ответов всех игроков. Текст карточки совпадает с обычным результатом: название слова, «Это был быстротест…» со всеми вариантами и «И вы…» с вашим сохраненным ответом. Список остается доступным, чтобы открыть другое слово.

В группе сначала нажмите «📊 Моя статистика» под сообщением бота: список и графики увидите только вы. Каждый участник открывает свою историю. Графики обновляются после новых ответов других игроков. Просмотр статистики не прерывает текущую игру или добавление вопросов. После сброса прогресса список ответов становится пустым.

Под карточкой с графиком и вашим результатом есть кнопка «📤 Поделиться» — в обычной игре, Автотесте и сохраненной статистике. Нажмите ее и выберите чат. Telegram подставит обычное сообщение, которое можно отредактировать и отправить от своего имени:

```text
Оказывается я император, узнай кто ты в Быстротесте
https://t.me/your_bot?start=question_42
```

Ссылка указана отдельной строкой, а сообщение отправляется без подписи `via @bot`. Превью ссылки формирует Telegram; оно зависит от доступности превью и настроек клиента или чата. Для новых кнопок inline-режим не требуется.

В сообщении используется ваш сохраненный результат без кавычек и ссылка на тот же вопрос. При переходе по ссылке и нажатии «Начать» бот сразу показывает этот вопрос первым, затем продолжает обычную игру. Если получатель уже отвечал на него, сохраненный ответ остается прежним и повторный голос не добавляется. Если вопрос удален или у него больше нет корректных ассоциаций, бот сообщает об этом и предлагает следующий доступный вопрос.

В черновик попадает результат, сохраненный в карточке. Ранее отправленные карточки с inline-кнопками продолжают работать по прежней схеме: для них включено превью ссылки, а подпись `via` остается. Им по-прежнему нужен включенный inline-режим в [@BotFather](https://t.me/BotFather) (`/setinline`).

Отправку выбранному получателю вы подтверждаете сами. Кнопка сохраняется при обновлении графика и после перезапуска. Новое поведение доступно на новых карточках; уже отправленные сообщения со старыми ссылками не меняются. Перед обновлением существующей установки выполните `python -m migrations.init_db`, чтобы добавить `chart_messages.reply_markup`; в Docker миграция выполняется автоматически.

## Автотест

В личном чате с ботом нажмите «Автотест» в меню после `/start` или отправьте `/autotest`. Бот ответит: «Вы будете получать новый Быстротест каждый день». Первое слово придет через 24 часа после включения, следующие — раз в сутки. Повторное нажатие или команда отключает рассылку с подтверждением: «Автотест отключен. Вы больше не будете получать ежедневные Быстротесты».

Каждый ежедневный вопрос содержит ассоциации для выбора. После ответа бот покажет соответствующий результат из `options` и статистику; следующий ежедневный вопрос придет через сутки. Обычная игра по «🎮 Быстротест» и `/play` доступна отдельно.

В группе или супергруппе «Автотест» в меню после `/start` или `/autotest` включает ежедневную отправку одного общего вопроса в этот чат. Первый вопрос придет через 24 часа. Ответить может любой участник, даже без запуска бота в личном чате. Выбранный ответ и диаграмма показываются только ответившему, а для остальных общий вопрос остается доступным — как в обычном Быстротесте. Следующий общий вопрос придет по расписанию, а не после чьего-то ответа.

Расписание общее для группы: повторное нажатие любым участником отключает ежедневную отправку в этот чат с подтверждением. Личные подписки и расписания других групп работают независимо. В одной группе вопрос отправляется один раз в сутки, независимо от числа участников. Уже отправленные в эту группу ежедневные вопросы не повторяются, даже если никто не ответил. Права администратора боту не нужны; достаточно возможности отправлять сообщения в группу.

Расписание и история отправленных слов хранятся в базе и сохраняются после перезапуска бота. В личном чате Автотест пропускает слова, на которые пользователь уже ответил, и ранее отправленные ежедневные вопросы, даже если они остались без ответа. Отключение и повторное включение не обнуляет эту историю. Если новых слов нет, бот ждет пополнения вопросов без повторных уведомлений. После простоя бот отправит один актуальный вопрос, затем продолжит раз в сутки. Проверка расписания выполняется раз в минуту. При блокировке бота рассылка отключается.

При обновлении существующей установки выполните `python -m migrations.init_db`, чтобы создать таблицы `autotest_subscriptions`, `autotest_deliveries`, `group_autotest_subscriptions` и `group_autotest_deliveries`, затем перезапустите бота. В Docker таблицы создаются автоматически при запуске.

## Игра в группе

Добавьте бота в группу и отправьте `/play` (или `/play@имя_бота`, если в группе несколько ботов). Также работает кнопка «🎮 Быстротест» в меню после `/start`.

На общий вопрос может ответить любой участник, даже если он не запускал игру. Каждый видит свой выбранный вариант и диаграмму статистики: общий вопрос заменяется результатом только у ответившего. Для остальных вопрос и кнопки остаются доступными.

После ответа следующий вопрос автоматически не появляется. Чтобы получить его, снова нажмите «🎮 Быстротест» или отправьте `/play`. Бот опубликует общий вопрос, на который еще не отвечал нажавший участник; ответить сможет каждый. Если у нажавшего вопросы закончились, бот сообщит об окончании игры. В личном чате вопросы по-прежнему идут автоматически после ответа.

После каждого ответа диаграммы этого вопроса обновляются у всех, кто уже получил результат, в группах и личных чатах. Подпись с личным выбором каждого участника сохраняется. Сброс прогресса тоже обновляет статистику. Ссылки на графики хранятся в базе, поэтому обновления продолжаются после перезапуска бота; удаленные и просроченные сообщения исключаются из списка обновлений. При временных сетевых ошибках или ограничении частоты запросов бот повторяет обновление с задержкой. Telegram не гарантирует доставку изменений персональных сообщений, когда пользователь офлайн.

При обновлении существующей установки выполните `python -m migrations.init_db`, чтобы создать таблицу `chart_messages`. В Docker это выполняется автоматически при запуске.

Для этого используются [персональные сообщения Telegram внутри группы (ephemeral)](https://core.telegram.org/bots/features#ephemeral-messages), включая `replace_callback_query_message` из Bot API 10.3. Права администратора боту не нужны: сообщения отправляются в ответ на нажатие кнопки. Если используется собственный сервер Bot API, требуется версия 10.3 или новее. Закрепленная версия aiogram передает новые параметры через дополнительные поля; недостающие методы редактирования определены в `bistro/ui/telegram_ephemeral.py`.

Персональные сообщения могут исчезать после перезапуска приложения Telegram. Можно снова нажать вариант в общем вопросе или отправить `/play`, чтобы продолжить. Прогресс хранится по пользователю и общий для группы и личного чата. Повторное нажатие показывает сохраненный ответ, не добавляя новый голос в статистику. `/reset` или «🔄 Сбросить прогресс» сбрасывает только ваши ответы.

## Добавление вопросов

Владелец может отправить `/add_question` в личном чате с ботом или нажать «➕ Добавить вопрос» в меню после `/start`:

1. Отправьте слово или короткий текст вопроса в одной строке, до 100 символов.
2. Отправьте от 2 до 8 результатов (`options`) через запятую, каждый до 64 символов, например: `повар, император`.
3. Отправьте столько же ассоциаций (`associo`) в соответствующем порядке, например: `салат, Рим`. Каждая ассоциация — до 64 символов; повторения недопустимы.
4. Проверьте пары «ассоциация → результат» и подтвердите добавление.

Для отмены отправьте `/cancel`. Новые вопросы сохраняются в базе и сразу доступны в игре, без перезапуска бота. Вопрос с уже существующим названием повторно не добавляется.

Доступ проверяется по `ADMIN_ID` на каждом шаге. Другие пользователи не могут добавлять вопросы, даже если знают команду.

### Массовое добавление

Отправьте `/add_questions` или нажмите «📚 Добавить вопросы» в меню владельца:

1. Отправьте до 50 названий вопросов через запятую, например: `Цезарь, Замок, Камера`.
2. Бот по очереди спросит результаты и ассоциации для каждого вопроса. Для «Цезарь» отправьте `повар, император`, затем `салат, Рим`, после чего переходите к следующему слову.
3. После последнего вопроса бот покажет весь список с парами «ассоциация → результат». Подтвердите сохранение одной кнопкой.

До подтверждения вопросы остаются черновиками. `/cancel` отменяет всю пачку без сохранения. Повторяющиеся названия в исходном списке нужно исправить; вопросы, которые уже есть в базе, при сохранении пропускаются. В конце бот сообщит, сколько вопросов добавлено и сколько пропущено.

### Ассоциации для существующих вопросов

В личном чате владельца отправьте `/add_associo` или нажмите «🧩 Добавить ассоциации». Бот по очереди предложит вопросы с пустым `associo`:

1. Посмотрите слово и пронумерованные результаты из `options`.
2. Отправьте ассоциации через запятую в том же порядке. Их количество должно совпадать с количеством результатов.
3. Проверьте пары и нажмите «✅ Сохранить». Бот сохранит ассоциации и предложит следующий незаполненный вопрос.

Чтобы заполнить или изменить ассоциации конкретного вопроса, отправьте его точное название после команды: `/add_associo цезарь`. В этом режиме после сохранения бот вернется в меню. `/cancel` или «❌ Отмена» отменяет текущий черновик; уже подтвержденные изменения сохраняются.

Вопросы с пустыми или некорректными ассоциациями не выдаются в Быстротесте и Автотесте. После заполнения они становятся доступны без перезапуска. Сохраненные ответы и статистика продолжают использовать `options`.

### Обновление базы для `associo`

Перед запуском обновленного бота выполните `python -m migrations.init_db`. В Docker эта команда уже выполняется автоматически при старте. Миграция добавляет `questions.associo` с пустым значением по умолчанию и сохраняет существующие вопросы, ответы и расписания. Повторный запуск безопасен.

Для старых вопросов заполните ассоциации через `/add_associo`. Скрипт `python -m migrations.add_questions` добавляет только отсутствующие слова и не перезаписывает уже существующие `options` или `associo`.

## Локальная установка

### Для установки выполните команды

`pip install -r requirements.txt`

`python -m migrations.init_db`

### Для запуска бота выполните

```bash
python -m bistro
```

Также поддерживается прежняя команда `python bot.py`.

### Проверка тестов

```bash
python -m unittest discover -s tests
```

## Запуск в Docker

### Предварительные требования

- Docker
- Docker Compose
- Переменная окружения `TOKEN` с токеном Telegram бота

### Запуск

1. Создайте файл `.env` в корне проекта с вашим токеном:
   ```
   TOKEN=your_telegram_bot_token_here
   ADMIN_ID=your_numeric_telegram_id
   ```

2. Запустите сервисы:
   ```bash
   docker-compose up --build
   ```

   Это запустит PostgreSQL базу данных и бота.

3. Для остановки:
   ```bash
   docker-compose down
   ```

### Миграции базы данных

После первого запуска, чтобы инициализировать базу данных и добавить вопросы, выполните:

```bash
docker-compose exec bot python -m migrations.init_db
docker-compose exec bot python -m migrations.add_questions
```

Или добавьте эти команды в Dockerfile или entrypoint, если нужно автоматизировать.
